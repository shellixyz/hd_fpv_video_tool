# 04: Replace chroma-key sidecars with packed-alpha sidecars

**What to build:** `generate-overlay-video` (and `transcode-video --osd-overlay-video`) produce an
MP4 sidecar that carries the overlay's real alpha channel, encoded with the normal hardware/software
encoder policy, and `play-video-with-osd` composites it in MPV without fringes, lost outlines, or
encoder padding showing.

**Blocked by:** None.

**Status:** done

## Why chroma keying cannot work here

Reviewed with the user's MPV screenshots `mpv-shot0001.jpg`..`mpv-shot0005.jpg` (untracked) and
the sidecars generated by tickets 01 to 03.

- Rendered OSD frames are heavily anti-aliased. Frame 300 of `DJIG0029.osd` has about 30,000
  partially transparent pixels for about 11,000 opaque ones. A chroma key is binary, so each of
  those pixels either keeps a share of the key color (a halo) or disappears (lost black outlines).
- 4:2:0 encoding averages chroma over 2x2 blocks, which spreads the key color into glyph edges
  regardless of the key chosen. A wider similarity removes outlines; a narrower one leaves fringes.
- AV1 VAAPI pads the coded width (1200 to 1216). FFmpeg's decoder returns the padded frame, so the
  overlay was mis-centered by 8 px and the opaque padding drew a dark bar at its right edge.

## Decisions

- **Packed alpha replaces chroma keying.** Each sidecar frame holds the overlay's straight RGB on
  the left and its alpha, as gray, on the right. Gray survives YUV conversion independently of
  the color matrix, so alpha is reproduced within compression error. Chroma-key output never
  shipped in a release, so it is removed rather than kept as an option, along with `--key-color`,
  `--osd-overlay-video-key-color`, and `--allow-untagged-opaque-osd`.
- **Side-by-side layout.** The alpha plane starts at the overlay width rounded up to a multiple
  of 64, so encoder blocks do not straddle the two planes. Side by side keeps a 1920x1080 overlay
  within the 4096x2160 limit common to hardware encoders, where stacking would not.
- **Explicit geometry.** The sidecar records `hd_fpv_overlay_mode=packed-alpha`,
  `hd_fpv_overlay_size=<W>x<H>` and `hd_fpv_overlay_alpha_x=<X>`. Playback crops those exact
  rectangles, so encoder padding never reaches the screen.
- Encoder selection, the bitrate cap, MP4 naming and discovery, silent output, and the transparent
  VP8/VP9 WebM compatibility mode are unchanged. Constant quality becomes per-codec; see `Built`.

## Built

- `PackedAlphaLayout` and `Frame::pack_alpha` in `src/osd/overlay.rs` pack each frame. Both
  generation paths feed FFmpeg the packed dimensions and record the mode and geometry metadata.
- `src/video.rs` parses the layout metadata and builds the MPV filter graph with
  `PackedAlphaLayout::unpack_filter`, the same fragment the fixture test uses.
- All chroma-key colors, collision checks, keying filters, `--key-color`,
  `--osd-overlay-video-key-color`, and `--allow-untagged-opaque-osd` are removed. `play_with_osd`
  has its original signature again.
- `tests/overlay_video_quality.rs` and `docs/overlay-video-quality.md` replace the chroma-key test
  and doc. The test composites source and decoded overlays over black and white, weights by
  visible pixels, and checks alpha error, alpha range, and the mode tag. The threshold is just above
  the 4:2:0 floor: a lossless 4:2:0 encode scores 2.45%, AV1 VAAPI 3.0%.
- Verified in MPV with the user's configuration at several timestamps of
  `DJIG0029_cut_transcoded.mp4`. There are no halos, lost outlines, edge lines or bar, and the
  overlay is centered. `play-video-with-osd` runs cleanly against the regenerated sidecar.

Gaps found along the way:

- Fixed here: the overlay encoder passed `-global_quality 90` to every VAAPI codec. That is a
  moderate AV1 quantizer but beyond H.265's 0-51 scale, so VAAPI H.265 sidecars were unusable
  (57% of visible pixels wrong). `packed_alpha_quality` now uses 90 for AV1, 24 for VAAPI H.265,
  and CRF 28 for software H.265, which measure 3.0%, 2.8-3.3%, and 3.3%.
- Not fixed: the default encoder is chosen by capability only. An overlay too large for the
  hardware encoder (packed width `align64(W) + W`, so above about 2048 px for 4096-wide encoders,
  as with 4K targets) would make FFmpeg fail rather than fall back to software.

Review fixes: the layout stores a `Dimensions` and reuses its parsing and display. The frame
senders take `Option<PackedAlphaLayout>` instead of a flag, and `Frame::pack_alpha` takes the same
layout whose geometry is recorded. The fixture test asserts the mode tag and the alpha range. The
review also confirmed VP8/VP9 output and playback are unchanged from `0606c33`.
